# 书签同步采用浏览器为事实源的对齐模型

书签同步（一键同步）以浏览器收藏为事实源：每次同步按浏览器全量快照对齐 StarNav 中 `sync_source='browser'` 的站点（新增/改标题/改URL/换分类/删除），手动书签（`sync_source='manual'`）永不参与。选择该模型而非增量导入、双向同步或本地优先：增量导入无法满足"完全对齐"诉求；双向同步需 StarNav 改动回写浏览器，复杂度高且浏览器侧无法承载 StarNav 的排序、可见性等本地属性；本地优先会破坏对齐一致性。

Status: accepted

## 决策要点

- **对齐范围**：仅 name、url、分类三字段；visibility、排序、访问次数、描述、logo 是 StarNav 本地属性，同步不碰。
- **配对键**：`url_key`（规范化 URL）为主键，扩展路径以浏览器书签 ID 辅助（URL 被改时原地更新 `url_key`）；多浏览器按 URL 合并、后同步者覆盖（last-write-wins）；HTML 文件路径无 ID，URL 被改 = 删旧插新。
- **手动优先**：浏览器书签 URL 撞手动书签时跳过，不新增不更新；手动书签永不被删除。用户可「解除同步」把同步书签转为手动书签。
- **删除安全**：同步删除前写 `operation_logs`（含被删 URL/标题/时间），可追溯不恢复；不做回收站。
- **分类**：文件夹拍平为「父/子」只新建；root 根（书签栏/其他书签/移动设备书签）不建分类，顶层项归「未分类」；分类改名/删除不传播。
- **Schema 迁移**：`sites` 加 `sync_source TEXT NOT NULL DEFAULT 'manual'`、`browser_bookmark_id TEXT`，加索引。

## Consequences

- 删除方向不可逆（仅日志追溯），误删依赖浏览器侧书签恢复。
- 空快照保护：同步快照不含任何书签时拒绝执行（服务端硬拦截 400），防浏览器同步故障/空导出导致全量误删；这也意味着"清空浏览器收藏以清空 StarNav 同步项"不可行，需手动删或批量解除同步。
- 同步项在 StarNav 的手动编辑会被浏览器状态覆盖——这是特性不是缺陷，需要「解除同步」入口承接保留诉求。
- 未来若引入回收站或本地优先，属于模型变更，需数据迁移与语义重审。
