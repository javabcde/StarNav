# 直属书签聚合节点：虚拟渲染而非真实分类

2026-08-16 grill-with-docs 会话。用户场景：父分类下有两个子分类，父分类自身也挂直属书签；希望侧边栏自动出现一个「直属书签」子节点，把这些直属书签聚合进去。分类聚合视图（点父分类显示子孙闭包书签）当时已存在，本决策只解决「直属书签的树内可见性」。

Status: accepted

## 决策要点

- **虚拟节点**：渲染期在分类树（首页侧边栏）/展平列表（插件站内浏览）合成「直属书签」节点，不建 `categories` 行、不改书签归属、不动 schema。不选真实分类行的原因：自动 INSERT 真实分类并改 `category_id` 会与书签同步对齐打架（浏览器收藏夹以文件夹结构为准，下次同步会重建/冲突），且不可逆；虚拟节点零数据风险、删渲染逻辑即回退。
- **双键过滤 `(catalog, direct)`**：虚拟节点同名（「直属书签」）可在多个父分类下共存，单名键必然歧义。Web 用 `?catalog=X&direct=1`，插件视图状态用 `{ catelog, direct }`；点击后只显示该分类直属书签（`category_id` 直接命中或 `catelog` 相等，**不含**子孙闭包）。
- **显隐条件**：`child_count > 0 && site_count > 0`——分类查询（categoryService 列表/树）已带两计数，零额外查询；无直属书签或无子分类不显示（叶子分类下节点与分类本身重复，纯冗余）。
- **排序**：真实子分类之后。
- **覆盖面**：首页侧边栏 + 浏览器插件站内浏览树。后台（无树导航）、搜索、统计、导出、同步对齐、grouped 布局组头一律不感知虚拟节点，节点不参与任何计数。
- **命名**：i18n key `directBookmarks`（直属书签 / Direct bookmarks）；CONTEXT.md 新增「分类域」术语（直属书签 / 分类子孙闭包 / 直属书签聚合节点）。

## Consequences

- **可逆**：纯视图层合成，删除即回退，无数据迁移。
- **扩展缓存形状不变**：`categories` 仍为 `[{ name, level }]`，合成节点带 `direct`/`parent` 标记；`popup-view-persist` 视图状态新增 `direct` 字段（来源正则锁同步更新）。
- **语义正交**：直属书签（归属层级轴）与同步书签/手动书签（来源轴）互不干扰——直属书签可以是同步来源也可以是手动。
