## Why

插件浏览视图的缓存只存"最近一次浏览的单个视图"（签名 = 关键词|分类|排序，30 条第一页）。切换分类/搜索/排序时缓存签名不匹配，必须重新请求接口（0.5~2s），违背"秒开"承诺。书签总量有限（500+ 条，~100-300KB JSON），全量缓存在存储上完全可行。

## What Changes

- 服务端 `/api/config` 新增全量模式 `all=1`：忽略分页返回当前 token 可见的全部书签（默认排序：创建时间倒序），可见性过滤逻辑与现有 `getSites` 完全一致。
- 插件缓存模型重构：`browse:cache:v1` 从"单视图第一页"改为"全部可见书签 + 分类树 + fetchedAt"。
  - **BREAKING**（缓存格式）：移除视图签名概念；旧单视图缓存读取时兼容渲染，下次拉取后自动升级为新格式。
- 打开行为：
  - 有新鲜缓存（TTL 内）→ 渲染缓存，**零请求**（除非收藏/同步触发重拉或手动刷新）。
  - 无缓存 → 骨架 + 文案初始化态（"正在初始化书签…"），全量到位后渲染。
  - 缓存过期 → 后台拉全量替换（先显示旧数据）。
- 收藏/同步成功后 → 重拉全量缓存（沿用 `refreshBrowseCacheAfterMutation` 等待在途任务的语义）。
- 浏览视图的搜索 / 排序 / 分类筛选（含子孙分类）/ 加载更多 → 全部改为**客户端过滤**（对全量缓存操作，零网络）。
- `popup-logic.js` 纯逻辑层演进：新增客户端过滤纯函数（关键词 LIKE、排序、分类含子孙、分页切片），缓存决策简化为"新鲜即渲染"；行为矩阵测试同步更新。
